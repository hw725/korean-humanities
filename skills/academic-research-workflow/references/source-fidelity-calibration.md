# 사료 충실성 감사 — 전거 앵커와 보정 (opt-in)

`사료 충실성 감사 / source-fidelity-audit`를 **기계적으로 검증 가능**하게 만들고, 감사기 자신의 오탐·누락을 측정하고 싶을 때만 읽는다. 기본 감사 표는 `output-contracts.md`의 Source-Fidelity Audit로 충분하다. 이 문서는 그 위에 세 가지 장치를 더한다.

> **출처(provenance).** 아래 메커니즘은 Academic Research Skills v3.8(`Imbad0202/academic-research-skills`, CC BY-NC 4.0)의 claim-faithfulness 보정 프로토콜에서 *방식만* 차용해 CJK 인문학 사료비평 맥락으로 재구성한 것이다. 텍스트·코드·임계값을 그대로 옮기지 않는다. STEM 단위(claim-citation tuple)를 사료 단위(주장-전거)로 바꾸고, 임계값은 잠정값으로 둔다.

## 1. 전거 위치 앵커 (locator anchor)

각 주장의 인용에는 **사료의 어디인지**를 가리키는 앵커를 단다. 앵커 없는 인용은 그 자체로 결함(아래 `anchorless`)이다. 「실록 기사가 존재함」(실재)과 「그 대목이 주장을 뒷받침함」(정합)은 다른 축이다 — 앵커는 후자를 검증 가능하게 만든다.

| `anchor.kind` | `anchor.value` 예 |
|---|---|
| `실록기사` | 『太宗實錄』 태종 5년 1월 1일 갑자 N번째 기사 + 기사 ID |
| `권면(엽)` | 『文集名』 卷3, 12b |
| `조목` | 『經國大典』 戶典 田宅조 |
| `직접인용` | 원문 직접 인용구(逐字) + 위 위치 |
| `단락` | 단락·장 단위(면 정보 없을 때, 약한 앵커) |
| `none` | 위치 없음 → `anchorless` 플래그 |

`output-contracts.md`의 감사 표에 `locator`(kind+value)와 `alignment` 두 열을 더해 쓴다.

## 2. 정합 판정 (alignment) — 실재와 분리

`source_existence`(실재: resolved/unresolved/fabrication-suspected)와 별개로, 앵커가 가리키는 대목이 주장을 실제로 뒷받침하는지 판정한다.

| `alignment` | 의미 |
|---|---|
| `뒷받침` | 사료가 주장을 직접 뒷받침 |
| `불일치` | 사료가 주장을 뒷받침하지 않음(또는 반대로 말함) |
| `모호` | 해석 여지가 커서 판정 유보(경쟁 독법 병기) |
| `원문확인불가` | 원문 대조 불가(예: 기계 국역만 있음) → 최대 `partially_verified` |

`불일치`는 `status: contradicted`로, `모호`는 강도 완화로 매핑된다.

복합 주장은 정합 판정 **전에** 逐句·표점 단위로 하위주장으로 분해하고(전거 둘 이상·독법 분기·복수 명제일 때만), 각 하위주장에 alignment를 매긴 뒤 약자 합성한다(`output-contracts.md`의 복합 주장 분해). 부분지지를 `모호`로 욱여넣지 않는다 — `모호`는 독법 경쟁축, 부분지지는 검증축이다. 하위주장 중 HIGH-WARN 제약 위반(아래 2·3·시대착오 등)이 있으면 합성 결과가 그 게이트를 상속한다(부분지지로 희석 금지). 이는 4절 보정의 과탐 방지(모호를 불일치로 남발 금지)와 함께 작동한다.

## 3. HIGH-WARN 게이트 — 초고 차단 신호

아래 다섯 부류는 초고·투고본에 남으면 **게이트로 차단**한다(사용자가 명시적으로 해제하기 전까지). 앞 네 가지는 기존 감사가 이미 개념적으로 다루지만, 별도 부류로 세워 보정(4절)의 측정 대상이 되게 한다.

1. `주장-사료 불일치` — `alignment: 불일치`. 사료가 주장을 뒷받침하지 않음.
2. `시대착오 인용` — 인용 사료가 입증 대상 사건·주장보다 후대(부정 제약 위반). 식민지기 편찬본(『고종실록』·『순종실록』)을 당대 사실 근거로 쓰는 경우 포함.
3. `사료 실재성 미상·날조` — `source_existence: fabrication-suspected/unresolved`. 존재하지 않는 사료·해소되지 않는 전거.
4. `전거 위치 없음(anchorless)` — 인용에 권·면·조목·기사 ID 등 위치 앵커가 없음.
5. `기계 국역 무대조 인용` — ITKC aitr 등 기계 국역을 원문 대조 없이 근거로 사용(핵심 원칙 3).

## 4. 감사기 자기 보정 (calibration) — opt-in, 기본 OFF

HIGH-WARN 신호는 감사기 판정이 신뢰할 만할 때만 쓸모가 있다. 과탐(모호를 불일치로 남발)은 거짓 차단을 양산해 신뢰를 무너뜨린다. 보정은 감사기를 **완벽하게 만드는 절차가 아니라, 배치 전에 그 오류 윤곽을 드러내는 절차**다.

**골드셋.** 사용자 사료에서 직접 만든 소규모 정답 묶음. 권장 출발점은 정합 12 + 시대착오·실재성 8 = 20개. 각 항목은 주장, 원문 발췌(정합용), 앵커, 그리고 전문가가 부여한 정답(`뒷받침/불일치/모호/원문확인불가` 또는 `위반/비위반`)을 가진다.

**측정.** 감사기를 골드셋에 돌려 누락률(FN: 잡아야 할 결함을 놓침)과 오탐률(FP: 멀쩡한 인용을 결함으로 표시)을 부류별로 낸다. 분모(`n_정답`/`n_비정답`)를 함께 적어 「n=0에서의 0.0」과 「n=8에서의 0.0」을 구분한다.

**임계값(잠정).** ARS는 FNR<0.15, FPR<0.10을 쓴다. 이는 STEM claim 단위에 맞춘 값이므로 **한문 사료비평에 검증된 값이 아니다.** 도메인 골드셋으로 실측하기 전에는 잠정값으로만 쓰고, 조이는 것은 근거를 남기고, 푸는 것은 감사기 개선 근거 없이는 하지 않는다.

**기본 OFF + 필요조건일 뿐.** 보정 통과는 감사기를 자동 신뢰할 *필요조건이지 충분조건이 아니다.* 통과해도 감사 결과는 사용자 확인 대상이다.

**골드셋 격리.** 정답셋은 **답을 생성·판정하는 에이전트의 컨텍스트에 동석시키지 않는다.** repo에 임베드하지 말고 런타임에 제공한다. 이유와 3계층 모델은 `hanmun-research-assistant`의 Evidence Access Layers(Layer 3 firewall)를 따른다 — 미리 본 정답에 맞춰 표면만 최적화하는 reward hacking을 막는다.

## 5. 이 절차가 고치지 못하는 것

- 골드셋 분포 밖 사료에 대한 성능(한 시대·한 장르·한 편찬자에 쏠린 골드셋은 쏠린 윤곽만 보고한다 — 군집 여부를 사용자가 점검한다).
- 표점·독법 자체의 타당성(그건 사료비평·교감의 일이다). 보정은 「감사기가 충실성 결함을 잘 잡는가」만 잰다.
- 해석의 개연성·정합성(핵심 원칙 5). 보정은 검증 대상(연대·인용·실재·정합)에만 적용한다.
