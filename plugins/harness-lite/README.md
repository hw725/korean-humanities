# harness-lite 사용 설명서 — 수강생판 확인 장치

AI가 《완료했습니다》라고 말할 때, 그 말 대신 **완료 조건을 실제로 돌린 기록(영수증)** 을 보게 하는 Claude Code 플러그인입니다.
지침 파일(CLAUDE.md)에 《검증하라》고 적어 두는 것만으로는 대화가 길어지면 잊힙니다. 훅(정해진 순간에 자동으로 도는 작은 프로그램)은 잊지 않습니다.

**Claude Code 전용입니다.** Codex·웹 챗봇에서는 동작하지 않습니다(훅이라는 장치가 Claude Code의 것입니다).

## 1. 설치

### 준비물: Python 3.8 이상

- **Windows**: python.org에서 받은 설치본을 씁니다. 설치 화면에서 《py launcher》를 꼭 포함하세요. Microsoft Store의 `python`은 쓰지 않습니다(실행해도 조용히 실패하는 안내 껍데기인 경우가 있습니다).
- **macOS**: 터미널에서 `python3 --version`이 3.8 이상이면 됩니다.
- 설치됐는지 확인: Windows PowerShell에서 `py -3 --version`, macOS 터미널에서 `python3 --version`.

Python이 없으면 확인 장치는 **꺼진 채로** 하루 한 번 화면에 알림만 띄우고, Claude Code 사용은 막지 않습니다. 알림을 보면 Python을 설치하세요.

### 플러그인 설치

Claude Code 안에서 입력합니다.

```
/plugin marketplace add hw725/korean-humanities
/plugin install harness-lite@korean-humanities
```

zip 파일(`harness-lite-<판>.zip`)로 받았으면 압축을 풉니다. 푼 폴더 안에 `.claude-plugin/marketplace.json`(이름이 `harness-lite-local`인 마켓플레이스)과 `plugins/harness-lite/`가 보여야 합니다. 그 폴더(두 항목을 바로 품은 폴더)를 마켓플레이스로 더합니다.

```
/plugin marketplace add <압축을 푼 폴더>
/plugin install harness-lite@harness-lite-local
```

`plugins/harness-lite/` 폴더만 따로 더하면 마켓플레이스 파일이 없어 설치되지 않습니다.

설치 뒤 Claude Code를 다시 시작하면 훅이 켜집니다.

## 2. 무엇을 막고 무엇을 확인하나

| 언제 | 하는 일 | 왜 |
|---|---|---|
| AI가 파일을 쓰거나 셸 명령을 돌리기 전 | **원본 쓰기 거부**: 어느 깊이에 있든 `원본/`·`primary_data/` 폴더와, 계약의 `protect`에 적은 경로 | 원본 자료는 한 번 덮어쓰면 되돌릴 수 없다 |
| 〃 | **영구 삭제 거부**: 명령 자리에 오는 `rm`·`rmdir`·`del`·`Remove-Item`과 `find -delete`·`git clean -f`. 대신 휴지통 명령을 알려 줌 | 실수로 지운 것을 휴지통에서 꺼낼 수 있게 |
| 〃 | **git으로 원본 덮어쓰기 거부**: `git restore`·`git checkout -- <경로>`·`git reset --hard`·`git stash`가 원본을 겨누거나, 원본이 든 저장소 전체를 겨누면 막음. git 저장소가 아닌 폴더에서는 git이 스스로 거부하므로 막지 않음 | 원본의 저장 안 된 변경이 한 번에 사라진다 |
| 〃 | **이름으로 끄기 거부**: `taskkill /IM`·`Stop-Process -Name`·`pkill`·`killall`(PowerShell `&` 뒤에 써도 같다) | 내가 열어 둔 같은 프로그램(한/글·브라우저)까지 닫힌다 |
| 〃 | **AI의 잠금 풀기 거부**: AI가 `harness.py unlock`을 부르면 막고, 사용자가 직접 칠 명령을 알려 줌. 영수증 보관소(`.harness/lite/`)를 AI가 고치는 것도 막음 | 잠금과 영수증은 AI가 스스로 풀거나 고치면 뜻이 없다 |
| AI가 《완료》라고 말할 때 | 계약 폴더를 고쳤으면, 고친 **뒤에** 돌린 영수증이 있고 그 뒤로 계약과 소스(계약의 `watch`에 적은 파일)가 안 바뀌었는지 확인. verify 출력을 잘라 읽어 영수증 줄이 안 보였으면, 그 프로젝트의 손대지 않은 최신 영수증이 지금 계약·소스와 같을 때 그것으로 확인 | 《돌렸다》가 아니라 《지금 이 코드로 통과했다》를 본다 |
| 〃 | 실패나 사람 판정 대기가 남았으면 《완료》를 막음 — AI는 고치거나 《완료하지 못했다》(실패 건수·조건 ID와 함께)·《미완료 — 사람 판정 대기 N건》으로 보고해야 함. 경고가 있으면 그 건수를 답에 적게 함 | 실패를 숨긴 《완료》를 막는다 |
| 〃 | 화면 캡처가 있으면 AI가 전부 열어 봤는지 확인 | 캡처를 《만들기만》 하고 안 보는 것을 막는다 |
| 〃 | 계약이 없는 폴더를 고치고 《완료》라고 하면, 그 세션에서 **한 번 막고** 계약 만들기를 권함. AI가 계약을 만들거나 필요 없는 사유를 밝히고 다시 끝내면 같은 세션에서는 다시 막지 않음 | 장치를 쓰기 시작하는 계기 |
| 〃 | Read가 잘렸거나(긴 파일) 일부가 가려졌는데 나머지를 안 읽었으면 《읽은 범위》를 행 범위 숫자와 함께(예: 《읽은 범위: 1-264행》) 밝히게 함 | 앞부분만 보고 전체를 아는 듯 답하지 않게 |
| AI 답에 《전수 … 완료》가 있을 때 | `확인 N / 전체 N` 꼴 개수가 없거나 두 수가 다르면 막음(표 안에 쓴 완료도 같다). 사용자가 《전수》를 말하면 전수 규칙을 AI에게 다시 알려 줌 | 표본만 보고 《전부 봤다》고 하지 않게 |

《경고》는 검사 출력에서 `HARNESS::WARN`으로 시작하는 표지가 붙은 줄입니다(`HARNESS::FATAL`은 곧바로 실패). 테스트 도구가 내는 일반 경고(예: pytest warning)는 세지 않습니다.

## 3. 처음 쓰는 법

1. 프로젝트 폴더에서 Claude에게 《완료 조건 계약 만들어 줘》라고 합니다.
2. Claude가 `harness.contract.json` 초안을 만들고 아홉 칸을 묻습니다: 목적·범위·근거·화면·자료·원본·검증·공개·비용. 모르는 칸은 비워 두어도 됩니다. 비운 칸은 영수증에 《빈 칸》으로 남습니다.
3. Claude가 보여 주는 **조건 표**를 읽고, 이것이 《끝난 상태》가 맞는지 확인해 주세요. **이 표가 장치의 기준입니다.** 표가 틀리면 장치도 틀린 채로 통과시킵니다.
4. 그 뒤로는 평소처럼 일을 시킵니다. AI가 《완료》라고 할 때 훅이 영수증을 확인하고, 모자라면 AI에게 다시 하라고 돌려보냅니다.

### 조건 하나 = 사람 말 한 문장 + 확인 명령 하나

판정자는 셋입니다.

| 판정자 | 뜻 | 꼭 적을 `check` 칸 | 《통과》로 세나 |
|---|---|---|---|
| `deterministic` | 명령의 종료 코드(테스트·검사 스크립트). 0이면 통과 | `check.argv`(명령 목록) 또는 `check.cmd`(명령 한 줄) | 예 |
| `visual` | 명령이 캡처(그림 파일)를 만들고, AI가 전부 연다 | `check.argv`(캡처를 만드는 명령)와 `check.captures`(캡처 파일 글롭 목록) | 캡처를 다 열었을 때까지만. 《보기 좋다》는 사람이 본다 |
| `human` | 사람 판정 대기열 파일(JSONL). 한 줄에 하나씩 `{"id": "q1", "status": "pending"}`이고, 판정을 마친 줄은 `"status": "decided"`. 대기가 0건이면 빈 파일을 둔다 | `check.queue`(대기열 파일 경로) | 아니오 — 대기가 남으면 《완료》가 아니다(《미완료 — 사람 판정 대기 N건》으로 보고). 읽을 수 없는 줄도 대기로 센다 |

세 판정자의 최소 예시입니다. `{python}`은 verify를 돌리는 파이썬으로 바뀌고, `{scratch}`는 조건마다 주어지는 작업 폴더입니다(검사 결과물은 소스 폴더가 아니라 여기에 씁니다).

```json
"conditions": [
  {"id": "C-001", "text": "테스트가 모두 통과한다", "judge": "deterministic", "check": {"argv": ["{python}", "-m", "pytest", "-q"]}, "status": "active"},
  {"id": "C-002", "text": "첫 화면이 시안과 같다", "judge": "visual", "check": {"argv": ["{python}", "capture.py", "{scratch}"], "captures": ["{scratch}/*.png"]}, "status": "active"},
  {"id": "C-003", "text": "번역 30곳을 사람이 확인했다", "judge": "human", "check": {"queue": "review/queue.jsonl"}, "status": "active"}
]
```

### 계약 파일의 칸

| 칸 | 뜻 |
|---|---|
| `intent` | 아홉 칸. 내가 말한 것은 `"source": "user"`, AI가 짐작한 것은 `"assumed"`, 빈칸은 `"blank"` |
| `watch` | 《소스》로 볼 파일. 여기 적힌 파일이 영수증 뒤에 바뀌면 다시 확인해야 한다. 기본값은 py·js·ts·html·css·md이므로, `.ipynb`·`.R`·`.json` 등을 고치는 프로젝트면 더한다 |
| `protect` | 읽기만 할 원본. 계약 폴더 기준 상대 경로(`"자료/원문/**"`)나 절대 경로(`"D:/연구/원본/**"`) |
| `conditions` | 조건 목록 |

## 4. Claude에게 시킬 수 있는 명령

Claude가 대신 돌립니다. 정확한 경로는 훅 메시지에 찍혀 나옵니다(Windows는 `py -3 "<플러그인 폴더>/scripts/harness.py" verify`, macOS·Linux는 `python3 "<플러그인 폴더>/scripts/harness.py" verify` 꼴).

| 명령 | 하는 일 |
|---|---|
| `harness.py init` | 계약 초안을 만들고, 테스트 명령을 찾으면 첫 조건에 넣는다. 조건 문장이 초안의 자리 표시(《(사람 말 한 문장으로)…》)로 남으면 verify가 거부한다. pytest가 없으면 그 사실을 알린다(설치는 하지 않는다) |
| `harness.py status` | 조건 표와 마지막 영수증. 영수증 뒤에 바뀌었으면 지난 결과에 《낡음》을 붙여 보인다 |
| `harness.py verify` | 조건을 전부 돌리고 `.harness/lite/<시각>/receipt.json`을 남긴다. 마지막 줄이 《통과》 또는 《완료 아님》(실패·문제·미실행 건수와 함께)이다. 필요한 모듈이 없으면 《pytest 모듈이 설치돼 있지 않습니다》처럼 사유를 적는다 |
| `harness.py trash <경로>` | 영구 삭제 대신 휴지통으로(원본·원본을 품은 폴더는 거부) |
| `harness.py lock` | 원본(`protect`·`원본/`·`primary_data/`)의 **지금 있는 파일**을 OS 읽기 전용으로 겁니다. 잠긴 파일에 쓰는 명령은 어떻게 쓰든 OS가 거부합니다. macOS·Linux에서는 원본 폴더도 잠가 새 파일 만들기·지우기·이름 바꾸기도 막습니다. Windows는 폴더를 잠그지 못해 원본 폴더 안에 **새 파일**을 만드는 것은 막지 못하고(그것은 훅의 원본 쓰기 거부가 맡습니다), 읽기 전용을 푸는 명령(`attrib -r`·`chmod`·`Remove-Item -Force`)도 막지 못합니다. 잠근 파일은 `.harness/lite/lock.json`에 기록합니다 |

**잠금 풀기는 사용자가 직접 합니다.** AI가 풀려고 하면 훅이 막습니다. `lock`을 걸 때 화면에 찍힌 명령을 PowerShell(macOS·Linux는 터미널)에 붙여 넣으세요. 모양은 이렇습니다.

```
py -3 "<플러그인 폴더>/scripts/harness.py" --root "<프로젝트 폴더>" unlock
python3 "<플러그인 폴더>/scripts/harness.py" --root "<프로젝트 폴더>" unlock
```

첫 줄은 Windows, 둘째 줄은 macOS·Linux입니다. 플러그인 폴더를 모르면 Claude에게 《unlock 명령 알려 줘》라고 하면 됩니다. `unlock`은 `lock`이 바꾼 파일·폴더만 원래 권한으로 되돌립니다(처음부터 읽기 전용이던 파일은 그대로).

`.harness/` 폴더는 영수증 보관소입니다. git을 쓰면 `.gitignore`에 `.harness/`를 넣으세요.

## 5. 전수 규칙

《전수》는 대상 전체 목록의 모든 항목을 하나씩 실제로 열어 확인하는 것입니다.
- 시작 전에 전체 개수 N을 먼저 정해 말합니다.
- 표본만 보기, 검색에 걸린 것만 보기, 이전 결과를 다시 쓰기는 전수가 아닙니다.
- 범위를 줄여야 하면 시작 전에 규모를 말하고 승인을 받습니다.
- 완료 보고에는 `확인 N / 전체 N`과 확인하지 못한 항목·사유를 적습니다.

## 6. 막혔을 때

| 보이는 메시지 | 뜻과 할 일 |
|---|---|
| 《원본(읽기만 할 자료)입니다》 | AI가 원본에 쓰려 했다. 결과는 다른 폴더에 쓰라고 하면 된다. 정말 바꿔야 하면 직접 하거나 계약의 `protect`를 고친다 |
| 《영구 삭제는 막혀 있습니다》 | AI가 휴지통 명령으로 다시 한다. 명령 자리가 아닌 낱말(검색어·도움말)은 막지 않는다 |
| 《완료 조건을 확인하지 않았습니다》 | AI가 고친 뒤 verify를 안 돌렸다. AI가 이어서 돌린다 |
| 《원본 잠금을 푸는 것(unlock)은 사용자만 합니다》 | AI가 잠금을 풀려 했다. 풀어야 할 이유가 맞으면 메시지에 찍힌 명령을 사용자가 PowerShell에 붙여 넣는다 |
| 《text 가 아직 초안의 자리 표시입니다》 | 조건 문장을 채우지 않았다. 《끝났다》를 사람 말 한 문장으로 적는다 |
| 《Python 3.8 이상을 찾지 못해…》 | 1절의 준비물을 설치한다 |

## 7. 한계

- **실수와 잊음을 막는 장치이지 보안 장치가 아닙니다.** 파일을 쓸 수 있는 AI는 마음먹으면 빠져나갈 수 있습니다(문자열을 조립한 명령, 파이썬 코드 안에서 지우기 등).
- **같은 사유로 세 번 막힌 뒤에는 더 막지 않습니다.** 끝없이 막히지 않게 하려는 것입니다. 그때는 화면에 《검증 없이 완료 주장》과 사유가 보이니, 그 메시지가 나오면 그 일이 실제로 끝났는지 사람이 봐 주세요.
- 읽은 범위는 밝힌 구간(파일·행 범위)마다 한 번만 묻고, AI가 일부러 구간을 정해 읽은 경우는 보지 않습니다.
- 계약의 조건은 하나 이상이 `"status": "active"`여야 하고, `status`는 `active`·`retired` 둘 중 하나입니다.
- 검사는 적힌 조건만 확인합니다. 그래서 3절 3번(표 확인)이 가장 중요합니다.
- 전체판(강사용)에 있는 계약 승인·검사 변조 방지·다른 AI 리뷰·순환 실행은 들어 있지 않습니다.
