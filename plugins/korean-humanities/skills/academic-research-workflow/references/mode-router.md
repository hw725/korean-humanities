# Mode Router (Humanities-First, v2.1.0)

이 파일은 `academic-research-workflow`가 어떤 연구 모드로 들어갈지 결정할 때만 읽는다. 기본 영역은 CJK 고전문학·역사학이며, 한문 텍스트 생산/표점 적용은 이 스킬이 아니라 `hanmun-philology`로 보낸다.

## 1. 문제설정 (research-scoping)

`문제설정 / research-scoping`을 선택한다.

- 주제, 관심 분야, 사료 더미만 있고 연구질문이 없음
- 제목은 있으나 대상 텍스트, 시기, close-reading 축, 비교 사료가 불명확함
- 무엇을 쓸지 같이 정하자고 요청함

첫 응답은 초안이 아니라 질문이다. 다음 축을 좁힌다.

- 연구 대상: 텍스트·사료, 시기, 인물·집단, corpus
- 문제의식: 지배적 독법의 빈틈, 논쟁점, 재해석 여지
- 사료 가용성: 원문 소재, 이본 유무, 국역·표점 상태
- 연구사 위치: 어느 학설·계보에 개입하는가
- 산출물: 논문, 발표문, 연구계획서

완료 기준은 답할 수 있는 연구질문 1-3개 + 제외 범위 + 연구사 좌표가 생기는 것이다.

## 2. 연구사 (historiographical-review) — 구 literature-review를 대체

`연구사 / historiographical-review`를 선택한다.

- 선행연구를 비판적으로 정리, 학설사·연구 동향
- 특정 문제를 학계가 어떻게 읽어 왔는지 계보를 그려야 함
- 논문 본문의 연구사 장을 준비함

이것은 PRISMA식 “남은 공백” 채우기가 아니다. **재독해·재맥락화**가 목표다. 필수 산출물은 **해석 계보도**: 학파(예: 실증사학 / 민족주의사학 / 사회경제사학 / 식민사학 비판 / 뉴라이트 논쟁) → 대표 연구·연구자 → 핵심 독법 → 그 독법이 가리는 것(은폐·침묵) → 이 연구의 개입 지점(개입의 핵심이 된 학설 충돌은 어느 두 연구가 어느 명제에서 갈리는지와 각자의 사료·판본 근거까지 짚는다 — 충돌을 전수 목록화하거나 ‘충돌 없음’까지 적지는 않는다). 단순 요약 나열로 끝내지 않는다.

## 3. 사료비평·교감 (source-criticism-collation) — 신규, 방법론의 척추

`사료비평·교감 / source-criticism-collation`을 선택한다.

- 사료의 진위·성립연대·전승·계통을 따져야 함
- 이본(異本) 대조, 교감, 변이 독법 정리
- 표점·句讀·懸吐 선택이 해석에 영향을 줌

이 모드는 **논증보다 먼저** 돈다. 출력은 논증 설계의 입력이 된다.

- **외적 비평**: 진위(眞僞), 출처·유래, 성립·편찬 연대, 전승·계통(recension).
- **내적 비평**: 저자 의도, 당파성·편향, 장르 규약, 침묵(무엇을 말하지 않는가).
- **교감**: 이본·계통을 정렬하고 변이를 **드러낸다**. 하나를 말없이 고르지 않는다.
- **표점·句讀·懸吐는 해석 행위**: 끊어 읽기가 의미를 바꾸면 경쟁 독법을 함께 제시하고 채택 근거를 단다. 표점의 **판단·정당화**는 여기(ARW), 디지털 텍스트에 **적용**은 `hanmun-philology`(D1).

필수 산출물은 사료비평 시트 + 이본 대조표 + 채택 독법 근거다.

## 4. 해석 논증 (hermeneutic-argument-planning) — 구 paper-planning/drafting

`해석 논증 / hermeneutic-argument-planning`을 선택한다.

- 논문 구조, 장 구성, 논증 지도를 원함 (planning)
- 연구질문·사료·핵심 근거·섹션 목적이 정해져 실제 문단·서론·결론 초고를 원함 (drafting)

원칙:

- **주제(thesis)·해석 주도**, 사료 근거 기반, 해석학적 순환(부분↔전체)으로 구성한다.
- 타당성 = 개연성 / 정합성 / 사료 충실성 / 경쟁 독법 설명력. 통계적 유의성·재현성이 아니다.
- 구조는 **주제별 또는 연대기**가 기본이다. IMRaD는 예외.
- 기여 = **연구사적 위치 설정**(2단계의 재독해)이지 “공백 메우기·지표 향상”이 아니다.

초고 전에 각 절의 핵심 주장과 사료 근거 상태를 확인한다.

## 5. 수정·심사 대응 (revision-response)

`revision-response`를 선택한다.

- reviewer comments, R&R, major/minor revision, 반박문, response letter

각 코멘트를 요구사항, 근거 필요성, 수용 여부, 본문 수정 위치로 분해한다. 감정 표현을 제거하고 검증 가능한 조치로 바꾼다. issue 유형은 이론·사료·해석·표점/번역·구조·연구사다(통계 제외). 우선순위는 공유 **심각도 등급 표준**(치명>주요>사소)을 따른다. 복합 코멘트는 약속(commitment) 단위로 분해해 이행을 추적한다 — 미이행이 근거 없이 남으면 `COMMITMENT_GAP`(투고를 막는 차단이 아니라 표면화 신호; `output-contracts.md`의 약속 이행 원장).

## 6. 인문학 피어리뷰 (peer-review)

`인문학 peer-review`를 선택한다.

- 논문 심사, 원고 평가, 독립 점검 요청

인문학 루브릭으로 평가한다.

1. 사료와 선행연구(연구사) 장악도 — 사료 기반의 폭과 적절성
2. 사료비평의 건전성 — 외적·내적 비평 수행, 연대·전승 판단의 방어 가능성
3. 문헌학적 정확성 — 한문 번역, 句讀·標點 선택
4. 해석의 독창성
5. 연구사 개입도 — 살아 있는 논쟁에 실제로 자리를 잡는가

보고는 결함을 **심각도 등급 표준**(`output-contracts.md`의 치명/주요/사소)에 따라 분류하고 판정 근거를 단다. **치명 결함이 하나라도 있으면 게재 불가(Accept 불가)로 판정한다.** **Risk-of-Bias·통계 방법·재현성 점검은 쓰지 않는다.**

## 7. 사료 충실성 감사 (source-fidelity-audit) — 구 claim-citation-audit

`사료 충실성 감사 / source-fidelity-audit`을 선택한다.

- 원문 인용 정확성, 국역 정확성, 인용-사료 대응, 연대 검증

주장 단위로 쪼개고 `verified / partially_verified / unverified / contradicted` 상태를 붙인다. 검사 항목:

- 원문 오인용(글자 단위 대조)
- 오역(국역 ↔ 원문)
- 연대·간지(干支)·음양력 환산, 왕대년↔서기 오류
- 인용-사료 충실성(인용 구절이 실제로 그 주장을 뒷받침하는가)
- **사료-사건 시대착오 순서검증**: 인용된 사료가 입증 대상 사건·주장보다 **앞서거나 동시대**인지 확인한다. 후대 편찬·이본(예: 식민지기 편찬 『고종실록』·『순종실록』, 사후 편찬 문집)을 동시대 1차 증거로 인용하면 flag한다(시대착오 sourcing).
- **사료 존재 검증**: 인용된 기사·전거가 실제로 해소·소재 확인되는지 — 실록 기사(왕대+干支+기사 ID) 해소, 文集 卷次·篇名 실재 — 를 로컬 코퍼스 + 한국고전종합DB·실록 DB에 대조한다(오인용과 구별, DOI 아님). 미해소 시 위조 의심으로 `unverified`.
- **기계 국역(ITKC aitr 등)은 초벌**: 원문 대조 전에는 최대 `partially_verified`, 인용 불가
- DOI·정책 등 최신 사실 확인은 보조 점검으로 유지(인문 고전 작업에서 결정적인 경우는 드묾)

## 8. (옵션) 체계적 코퍼스 선별 (systematic-review) — DH opt-in

`systematic-review`는 **기본 경로가 아니다.** 사용자가 명시적으로 대규모 코퍼스 선별·동향 조사를 요청할 때만 선택한다.

- 文集 코퍼스 구축, KCI 동향 대량 조사, 대규모 이본 목록처럼 **재현 가능한 선별 로그가 실제로 필요한** DH 작업
- 검색 소스·검색식·날짜·포함/제외·dedup·screening checkpoint를 정하고, 100건 이상이면 shard·resume 계획을 먼저 만든다

해석 중심 연구의 기본 사료비평을 PRISMA로 대체하지 않는다(그러면 형식만 남는다).

## 9. (옵션) DH 평가 프로토콜 (experiment-planning) — 얇은 stub

`experiment-planning`은 텍스트 기반 고전 연구에는 부적합하므로 기본 비활성이다. **경험적 디지털 인문학**일 때만 얇게 쓴다.

- annotator 일치도 연구, 독자 실험, OCR/NER 평가 프로토콜, retrieval 평가
- 산출물: 평가 설계, 측정 지표, 재현성 리스크. 실제 데이터가 있으면 `research-file-management` 규칙을 먼저 적용한다

그 외 일반 고전·사학 논문에서는 이 모드를 권하지 않는다.

## 10. 전체 파이프라인 (full-pipeline) — 인문학 순서로 재배열

`full-pipeline`을 선택한다. 권장 순서:

1. 문제설정 (연구질문 + 연구사 좌표)
2. **사료비평·교감** (진위·연대·전승·이본·표점)
3. 연구사 (해석 계보도)
4. 해석 논증 설계와 초고
5. 사료 충실성 감사 (원문·국역·연대)
6. 인문학 피어리뷰 또는 교차검증
7. 수정과 response matrix
8. 형식 변환(HWP/HWPX)과 제출 점검

각 단계는 입력, 산출물, 통과 기준, 미해결 리스크를 남긴다. (구 STEM 순서의 검색→screening→dedup은 8번 DH 옵션일 때만.)
