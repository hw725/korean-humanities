# 원고-데이터 정합 감사 (manuscript-data-consistency)

투고·수정 제출 직전, 원고에 인용된 **모든 수치**(표본 수·백분율·검정 통계량·표·예문 건수·데이터 공개 수량)를 데이터 저장소의 정본 산출물과 **전수 대조**하는 모드. 사료 충실성 감사(source-fidelity-audit)가 ‘주장↔사료’를 다룬다면, 이 모드는 ‘원고 수치↔데이터 정본’을 다룬다.

## 왜 전수 대조인가 — 체크리스트의 맹점

데이터 정제·표본 재추출 후 원고를 고칠 때 흔히 ‘수정 필요 항목 체크리스트’를 만든다. 체크리스트 기반 검증의 구조적 결함: **목록에 있는 항목은 몇 번을 검증해도 통과하고, 목록에 빠진 항목은 영원히 보이지 않는다.** 체크리스트가 특정 절(예: 재분석한 장)의 산출물에서 파생되면, 정제의 영향이 미친 다른 절의 수치는 목록 자체에 오르지 않는다.

따라서 규칙은 하나다:

> **데이터 정제·표본 변경의 영향 범위는 ‘재분석한 절’이 아니라 ‘원고 전체의 수치’다. 검증 단위는 체크리스트가 아니라 원고 전문이다.**

## 트리거 시점 (의무)

1. 투고 직전 (최종본 확정 전)
2. 심사 수정본 제출 직전
3. **데이터 정제·표본 재추출·코퍼스 변경 직후** — 원고가 아직 수정 중이어도 영향 수치 목록을 먼저 만든다
4. 데이터 공개 저장소 URL을 원고에 인용하는 경우 — 저장소 재계산값과 원고값의 일치가 재현성 주장의 전제다

## HWP 전환 이후가 진짜 위험 구간

한국 학술지 투고는 최종 편집이 거의 항상 HWP에서 일어난다. 마크다운 초고 단계의 동기화 규율만으로는 이 사고를 막을 수 없다 — **md → HWP 이관 시점부터 저장소의 md는 더 이상 원고의 진실이 아니다.** 따라서:

1. 이관 직후, HWP 파일을 대상으로 1차 전수 대조를 돌려 기준선을 만든다
2. 이후의 모든 감사는 **제출할 실제 HWP 파일**을 직접 읽는다 (아래 레시피·도구 — 한글 프로그램 실행 불필요)
3. md와 HWP가 공존하는 기간에는 HWP가 우선 검증 대상이다

## 도구

`scripts/verify_manuscript_numbers.py`가 아래 2~4단계를 자동화한다. HWP·HWPX·MD·TXT 입력을 받아 정본 JSON(복수 가능)과 대조하고, `--old`에 구버전 JSON을 주면 구버전 잔존을 검출한다(가장 신호가 강한 검사). Windows는 `py`로 실행하며 HWP 입력만 `olefile`이 필요하다.

```bash
py scripts/verify_manuscript_numbers.py 투고본.hwp --stats results/final_stats.json --old archive/구버전_stats.json --report 대조표.md
```

## 절차

### 1단계: 정본 지정

수치의 단일 기준 파일(canonical stats)을 확정한다. 예: `results/final_stats_*.json`. 정본이 둘 이상이거나 ‘중간 산출물’과 섞여 있으면 감사 전에 먼저 정리한다. 구버전 산출물은 archive로 격리하고 경로에 날짜를 박는다.

### 2단계: 원고 수치 전수 추출

원고 파일에서 숫자를 기계적으로 추출한다. 사람이 눈으로 고르지 않는다.

- MD·TXT: 정규식으로 수치 토큰 추출
- **HWP (GUI 없이)**: olefile 직접 파싱 — 아래 레시피. 한글 프로그램 실행이 필요 없다
- HWPX: zip 해제 후 section XML에서 텍스트 추출
- PDF: 텍스트 레이어 추출 (깨진 구결·옛한글은 `gugyeol-decode` 위임)

```python
# HWP 5.0 본문 텍스트 추출 (표 내용 포함, 의존성: olefile)
import olefile, zlib, struct

ole = olefile.OleFileIO(path)
compressed = ole.openstream('FileHeader').read()[36] & 1
INLINE = {4,5,6,7,8,9,19,20}; EXTENDED = {1,2,3,11,12,14,15,16,17,18,21,22,23}

def extract(name):                      # name: 'BodyText/Section0', 'Section1', ...
    data = ole.openstream(name).read()
    if compressed: data = zlib.decompress(data, -15)
    out, i = [], 0
    while i + 4 <= len(data):
        (hdr,) = struct.unpack_from('<I', data, i); i += 4
        tag, size = hdr & 0x3FF, (hdr >> 20) & 0xFFF
        if size == 0xFFF: (size,) = struct.unpack_from('<I', data, i); i += 4
        payload = data[i:i+size]; i += size
        if tag == 67:                   # HWPTAG_PARA_TEXT
            j = 0
            while j + 2 <= len(payload):
                (ch,) = struct.unpack_from('<H', payload, j)
                if ch in EXTENDED or ch in INLINE: j += 16; continue
                out.append('\n' if ch in (10, 13) else (chr(ch) if ch >= 32 else '')); j += 2
    return ''.join(out)
```

천단위 콤마를 제거한 사본(`text.replace(',', '')`)으로 매칭하면 `2,853`/`2853` 표기 차이를 흡수한다.

### 3단계: 양방향 대조

- **정본 → 원고**: 정본의 모든 보고 수치가 원고에 존재하는가 (누락 검출)
- **원고 → 정본**: 원고의 모든 수치가 정본에서 재계산되는가 (구버전 잔존·날조 검출)
- 유도값(백분율·차이·배수)은 모수에서 재계산해 검산한다. V = √(χ²/N) 같은 역산으로 출처 상태를 특정할 수 있다

### 4단계: 불일치 분류

| 유형 | 예 | 처치 |
|---|---|---|
| 구버전 잔존 | 정제 전 표본 수가 일부 표에 남음 | 갱신 대응표 작성 (구 값 → 신 값) |
| 원고 내부 모순 | 표의 n과 데이터 공개 문장의 수량이 서로 다른 데이터 상태 | 어느 상태로든 통일 — 저장소 상태와 무관하게 정정 필수 |
| 서술 층위 차이 | ‘원시 총량’ vs ‘정제 후 분석 입력’ | 오류가 아닐 수 있음 — 층위를 본문에 명시해 해소 |
| 정본 미수록 | 원고에만 있는 수치 (보조 계산 등) | 정본 산출 스크립트에 편입하거나 산출 근거를 로그로 남김 |

### 5단계: 산출물

1. **전수 대조표**: 원고 위치(표·절) | 원고 값 | 정본 값 | 판정(일치/구버전/모순/층위)
2. **갱신 대응표**: 교정·수정 제출 때 그대로 쓸 수 있는 구 값 → 신 값 표
3. **판정 요약**: 결론(효과 방향·등급)이 두 상태에서 같은지 — 같다면 정오(訂正) 사안, 다르면 분석 재검 사안

## 정제 결정 동기화 규칙

- 정제·제외 결정은 실행 시점에 **사유와 함께 단일 표현으로** 기록한다 (예: ‘과잉 대표 보정’). 같은 결정을 문서마다 다른 말(‘오염 제거’ 등)로 부르면 감사가 어긋난다
- 정제 직후 ‘영향받는 원고 수치 전수 목록’을 만들어 interim_reports에 남긴다 — 원고 수정은 이 목록이 아니라 **원고 전문 재대조**로 닫는다 (목록은 작업 보조일 뿐)
- 투고 시점에는 `research-file-management`의 submission-freeze로 데이터·산출물 상태를 동결하고, 동결 해시를 원고 버전과 묶어 기록한다

## 실패 모드

| 상황 | 대응 |
|---|---|
| 투고 후 불일치 발견 | 당황 금지 — 결론 영향 판정부터. 방향 불변이면 corrigendum 사안. 동결·커밋 타임스탬프가 사후 조작 의혹을 차단하는 무죄 증거다 |
| 정본이 여럿 | 감사 중단, 정본 단일화 먼저 |
| 원고가 HWP뿐이고 추출 실패 | 한글 프로그램 변환(hwpx/txt) 후 재시도. 그래도 안 되면 표 단위 수동 대조로 강등하되 ‘전수’ 원칙 유지 |

## 금지 패턴

- 재분석한 절의 체크리스트만 갱신하고 ‘반영 완료’로 종결하기
- 점검 표의 ✅를 ‘원고 전체가 최신’의 증거로 읽기 — ✅는 그 행 하나의 증거다
- 데이터 공개 수량·코퍼스 총량 같은 ‘본문 밖 수치’(데이터 가용성 문장, 각주, 초록)를 대조 범위에서 빼기
