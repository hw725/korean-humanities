# 논문 구조분석 (Paper Structure Analysis)

논문 한 편이 **어떻게 짜여 있고 어떤 근거로 어떤 결론에 이르는지**를 장절 트리를 뼈대로 드러내는 노트 한 장을 만든다. 단편 요약이 아니다.
트리도 노트도 이 스킬을 따르는 에이전트가 본문을 직접 읽고 만든다. 출력은 한국어다.

## 왜 트리를 직접 만드는가

자동 구조 추출기(레이아웃 통계형·LLM 목차 매핑형)와 직접 작성을 같은 논문 8편으로 대조한 결과(2026-10-22), 시작 쪽이 틀린 노드가 직접 작성 0개, 레이아웃형 6개, 목차 매핑형 2개였다.
레이아웃형은 글자층이 깨진 PDF에서 깨진 글자를 제목으로 그대로 베낀 트리를 성공으로 냈다(30회 중 4회). 목차 매핑형은 목차 쪽을 절 시작으로 잡았다.
그래서 이 스킬은 외부 추출기를 기본으로 쓰지 않는다. 이미 만든 트리가 주어지면 본문과 대조만 한다(§3).
「노드 제목이 그 쪽 글자층에 있는가」만으로 트리를 매기지 않는다 — 깨진 글자층을 베낀 제목도 맞은 것으로 센다.

## 1. 입력 (논문마다)

| 이름 | 내용 |
|---|---|
| text | 본문 텍스트(PDF 추출본 또는 OCR 본). `<!-- page N -->` 표지가 PDF 물리 쪽 번호다 |
| pdf | 원본 PDF. 텍스트의 쪽수·숫자가 이상할 때 글자층과 대조한다 |
| tree | 트리 JSON을 쓸 경로. 이미 있는 트리를 대조만 할 때는 그 경로 |
| out | 쓸 노트 경로. 이름은 지시에 주어진 그대로(다른 노트의 링크가 끊기지 않게) |
| old_summary | (있으면) 기존 요약 노트. 본문으로 확인한 것만 옮긴다 |
| binding | (있으면) 지식 저장소의 바인딩 문서 — 프런트매터 추가 키·태그·링크 대상·정확성 규칙 경로 |

바인딩 문서가 이 스킬과 다르게 정한 것(경로·태그·추가 프런트매터)은 바인딩을 따른다. 절차·노트 형식·검사는 이 스킬이 정본이다.

## 2. 읽기 — 전수

- text를 **처음부터 끝까지 전부** 읽는다. 표본 읽기를 하지 않는다. 큰 파일은 offset·limit으로 나눠 끝까지 읽는다.
- 읽지 못한 쪽이 있으면(빈 쪽·깨진 글자) 그 쪽 번호를 검증 메타데이터에 적는다.
- **알려진 추출 결함**: 같은 숫자가 이어지면 하나로 줄여 먹는 추출기가 있다(1922→192, 300年→30年). 연도·쪽수·수치가 이상하면 PDF 글자층과 대조해 PDF 값을 쓰고, 원문 인용은 text 글자 그대로 두되 검증 노트에 적는다.
- 스캔본은 PDF에 글자층이 없으니 OCR 본만 근거로 쓴다. PDF를 열어 보려면 스크립트를 파일로 써서 실행한다(셸 heredoc 금지).

## 3. 트리

**만들 때(기본)** — 본문의 장절 제목으로 만든다. 첫 쪽에 목차가 있으면 목차와 본문 제목을 둘 다 본다.

```json
{"doc_name": "<PDF 파일명>", "generator": "<모델명> from <text 원천> (<날짜>)",
 "structure": [{"title": "Ⅰ. 서론", "node_id": "0000", "start_index": 1, "end_index": 3,
                "summary": "<본문 근거 1～2문장>", "nodes": []}]}
```

- `start_index`·`end_index`는 PDF 물리 쪽(`<!-- page N -->`)이다. 지면 쪽수가 아니다.
- `node_id`는 전체 순회 순서대로 `0000`부터 빈틈없이 매긴다.
- 제목은 인쇄된 번호까지 지면 그대로 쓴다(「Ⅰ.」「1.」). 풀어 쓰거나 번역하지 않는다 — 검사기가 제목을 지면과 대조한다.
- `summary`는 논문 언어와 관계없이 한국어로 쓴다. 인명·서명·용어는 원어를 그대로 둔다. 검사기는 한국어가 아닌 요약을 오류로 낸다(2026-10-27 — 일본어·중국어 요약이 RefManager에 그대로 보였다).
- 국문·영문 초록, 참고문헌은 있으면 따로 노드로 둔다. 본문 절에 섞지 않는다.
- 나누는 깊이는 저자의 장절 체계를 따른다. 저자가 번호를 매기지 않은 단위(인용 작품 하나하나 등)를 노드로 쪼개지 않는다.
- 쓴 뒤 `scripts/check_structure.py tree`로 검사한다.

**주어졌을 때(대조만)** — 본문 첫머리·본문 속 장절 제목과 트리를 대조해 검증 메타데이터에 「지면 장절과 일치」 또는 「불일치: (무엇이 어떻게)」로 적는다. 트리가 틀렸으면(절 누락·쪽 범위 어긋남·참고문헌을 본문 절로 삼킴) 노트의 논증 지도는 **본문 장절 기준으로 바로잡아** 쓰고, JSON은 건드리지 않는다.

## 4. 노트

형식은 [references/page-format.md](references/page-format.md)가 정본이다 — 프런트매터, 절 11개의 순서와 제목, 각 절에 넣을 것.

**정확성 규칙**(바인딩이 별도 규칙 문서를 주면 그것도 읽는다):
- 소스에 적힌 것만 쓴다. 검증 안 된 것은 쓰지 않는다. 모르면 빈칸으로 둔다.
- 깨진 변환물은 근거가 아니다.
- 「아마도」「~로 보인다」「~일 가능성이 높다」「약」「대략」을 쓰지 않는다(원문 인용 안은 예외).
- 외부 지식으로 「이 논문은 틀렸다」를 쓰지 않는다. 텍스트 안에서 확인되는 구조적 사실만 쓴다.
- 문장마다 「본문 어디에 있는가」를 스스로 확인한다.

**표기**: 코드 블록·프런트매터 밖에서는 직선 따옴표를 쓰지 않는다 — `“ ” ‘ ’`. 서명 『』, 편명 「」〈〉. 범위 물결표는 전각 `～`(ASCII `~`는 취소선 사고). 한문 서명·인명은 원표기, 독음은 본문에 나온 것만. 분량은 논문의 뒷받침에 비례한다.

## 5. 끝내기 전 검사 (필수)

검사기는 `regex` 모듈 하나를 쓴다 — 처음 한 번 `python -m pip install -r requirements.txt`.

```
python scripts/check_structure.py tree <tree.json> --text <text.md>
python scripts/check_structure.py page <out.md> --text <text.md> --tree <tree.json>
```

`--tree`는 트리를 직접 만들었을 때만 준다 — 주어진 트리를 바로잡아 쓴 노트는 논증 지도 행 수가 트리 노드 수와 다른 것이 정상이다(§3).
검사기가 보는 것: 트리 JSON 파싱·`node_id` 순서·쪽 범위(1～마지막 쪽, 시작 ≤ 끝, 하위 노드가 상위 범위 안)·형제 순서 / 노트의 프런트매터 키·절 순서·논증 지도 행 수 = 트리 노드 수·원문 인용이 text에 글자 그대로 있고 적힌 쪽에 있는지·본문의 직선 따옴표와 ASCII 물결표·mermaid 라벨 형식.
검사기가 못 보는 것(스스로 확인): 핵심 주장·논증상 기능이 본문과 맞는지, 결론의 빈틈이 텍스트로 뒷받침되는지.
오류가 0이 될 때까지 고친다. 인용을 text에서 못 찾으면 지운다 — 고쳐 쓰지 않는다.

## 6. 여러 편 — 한 편당 에이전트 하나

- 논문마다 에이전트 하나를 붙여 병렬로 돌린다. 한 에이전트에 여러 편을 맡기면 뒤 편일수록 읽기가 얕아진다.
- 에이전트에게 주는 것: 이 SKILL.md와 page-format.md 경로, §1 입력 표, 바인딩 문서. 쓸 수 있는 경로는 tree·out 둘뿐이라고 못박는다.
- 비교·재작성 작업이면 기존 트리·노트 폴더를 열지 말라고 적는다 — 기존 결과에 끌려간다.
- 경로를 줄여 적지 않는다(「…\direct」 같은 생략은 엉뚱한 폴더에 쓰게 만든다). 전부 절대 경로로 준다.
- 돌아온 결과는 오케스트레이터가 §5 검사기를 다시 돌려 확인한다. 에이전트의 「통과」 보고만 믿지 않는다.

## 7. 하지 말 것

- 기존 요약 노트를 고치거나 옮기거나 지우지 않는다(교체는 오케스트레이터가 한다).
- 지식 저장소의 색인·로그·작업 규칙 파일을 건드리지 않는다.
- 지정된 tree·out 경로 밖에 파일을 쓰지 않는다.
