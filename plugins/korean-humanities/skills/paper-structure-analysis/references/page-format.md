# 구조분석 노트 형식 (정본)

`scripts/check_structure.py page`가 이 문서의 프런트매터 필수 키와 절 제목·순서를 검사한다. 바꾸면 검사기의 `REQUIRED_KEYS`·`SECTIONS`도 같이 고친다.

## 프런트매터

```markdown
---
title: "<저자(한자 있으면 병기)>, 「<제목>」(<연도>)"
description: "<한 줄: 무엇을 어떤 근거로 어떻게 논증하는가>"
source_path: "<원본 PDF 경로>"
structure_tree: "<트리 JSON 경로>"
structure_generator: "<Claude (본문 직접) | 외부 추출기 이름 (대조 결과)>"
sources: ["<원본 PDF 경로>"]
created: <YYYY-MM-DD>
---
```

필수 키는 위 일곱 개다. 지식 저장소가 더 요구하는 키(type·tags·검증 층위·교체 대상 등)는 바인딩 문서를 따라 덧붙인다.

## 본문 절 (이 순서, 이 제목)

1. `# <title과 같은 제목>`
2. `## 서지 정보` — 저자·연도·게재지(권호·쪽)·영구 링크. 지면(러닝헤드·첫 쪽 각주)에서 확인한 것만. 기존 요약의 서지 불일치 기록은 본문으로 다시 확인해 유지한다.
3. `## 한눈에 보는 논증` — 세 줄: **연구 질문**(저자가 세운 물음) / **중심 논지**(저자의 답, 1～2문장) / **자료와 방법**(무엇을 어떻게 읽었나).
4. `## 논증 지도` — 트리 노드마다 한 행인 표:
   `| 절 | 쪽(PDF / 지면) | 논증상 기능 | 핵심 주장 | 근거 |`
   - 기능은 짧은 명사구: 문제 제기, 연구사 검토, 개념 정립, 배경 서술, 자료 제시, 사례 분석, 비교, 반론 처리, 종합, 전망 등.
   - 근거 칸: 그 절이 실제로 쓰는 1차 사료(작품·문헌명·권차)·표·통계·선행연구. 구체적으로.
   - 지면 쪽수는 러닝헤드 등으로 확인될 때만 쓰고, 아니면 PDF 쪽만.
   - 표 아래, 장(최상위 노드)마다 2～4문장: 이 장이 앞 장에서 무엇을 받아 다음 장에 무엇을 넘기는가.
5. `## 논증 흐름도` — mermaid `flowchart TD` 블록 하나. 노드 = 연구 질문 → 장·절별 하위 주장 → 결론. 노드 라벨 앞에 절 번호. 간선 라벨은 관계(전제 / 사례 / 대조 / 확장 / 귀결). 노드 15개 안팎. 라벨은 `["..."]`로 감싸고 간선 라벨은 `-->|라벨|`.
6. `## 근거의 구성` — (a) 1차 사료: 자료명과 어느 절에서 무엇을 입증하려고 쓰였는지 (b) 선행연구 의존: 누구를 받아들이고 누구를 비판하는지(절·각주 번호) (c) 표·도판·통계가 있으면 무엇을 보여주는지.
7. `## 결론의 지탱 구조와 빈틈` — 결론부의 주장 하나하나에 대해 어느 절이 받치는가, 근거의 양(사례 몇 개·자료 몇 종). 이어서 **구조에서 관찰되는 것**만: 결론에 본문에서 다루지 않은 주장이 들어감, 사례가 특정 시기·장르에 몰림, 개념 정의 없이 사용, 저자 스스로 밝힌 한계(인용).
8. `## 학술 대화` — 이 논문이 계승·비판·확장·대안·주석하는 연구. 유형 라벨(계승(builds on)·비판(critiqued by)·확장(extended by)·대안(alternative)·주석(comments on))과 근거 절·각주. 지식 저장소에 그 연구의 노트가 있으면 링크한다(파일이 실재하는지 확인한 것만).
9. `## 기존 위키와의 연결` — 인물·작품·개념 노트 가운데 실재하는 것만 링크한다. 기존 요약에 있던 개념 링크는 유지한다.
10. `## 원문 인용` — 3～5개. 인용 블록 고정: 첫 줄 `> 원문 그대로 (PDF p.N)`, 필요하면 다음 줄 `> — 출처 설명`. 인용 블록 사이는 빈 줄. **text에 글자 그대로 있는 것만**. 한문은 원문 그대로, 필요하면 저자의 번역을 따로 인용한다.
11. `## 검증 메타데이터`
    - **소스 파일**: 원본 PDF 경로
    - **텍스트 원천**: text 경로와 무엇인지(PDF 추출본 / OCR 본(엔진·날짜))
    - **구조 트리**: 경로 · 생성기 · 지면 장절 대조 결과
    - **검증 범위**: 전문 (PDF p.1～p.N) — 실제로 읽은 범위. 못 읽은 쪽이 있으면 적는다
    - **최종 검증일**: YYYY-MM-DD
    - **검증 노트**: 추출·OCR 오식 의심 구절(쪽), 이전 요약에서 고치거나 뺀 것과 이유
